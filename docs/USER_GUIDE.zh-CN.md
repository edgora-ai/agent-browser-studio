# Agent Browser Studio 使用手册

Agent Browser Studio 是一个本地桌面控制台：在自研补丁版 Chromium 引擎（可选 Firefox）上管理隔离浏览器 profile，配套代理管理、AI 自动化、持久化任务、审计追踪和 S3 团队同步。

> 仅将本产品用于合法且获授权的场景。禁止用于欺诈、垃圾营销、凭据攻击、未授权抓取、平台滥用、封号规避，或滥用 cookie、凭据、个人数据与机密信息。详见 [ACCEPTABLE_USE.md](../ACCEPTABLE_USE.md)。

## 0. 控制台一览

## 1. 安装与运行

当前要求：**Apple Silicon macOS**、Node.js 22.16+，以及放入受管缓存的独立构建 Chromium。

```bash
git clone https://github.com/edgora-ai/agent-browser-studio.git
cd agent-browser-studio
npm install
npm start
```

从预构建的 Chromium.app 安装引擎：

```bash
npm run verify:chromium -- /path/to/Chromium.app
npm run install:chromium -- /path/to/Chromium.app
```

Windows / Linux 代码路径已存在但尚未端到端验证；提供无头服务器模式（`--headless`）与 Docker 镜像用于 CI。

**引擎缺失时不会死胡同**：配置页顶部出现横幅，提供「选择本地构建…」和「安装指南」两个按钮，首启向导里也有同样的出路。

## 2. 首次运行

没有引擎或没有 profile 时会出现 4 步向导：

1. **校验受管 Chromium**——确认引擎，或选择本地构建。
2. **创建第一个 profile**——只需填名字。
3. **启动与风险检测**——启动 profile 并打开指纹检测页。
4. **配置 AI 智能体（可选）**——跳转到 Agent 配置。

「暂时跳过」仅本次会话隐藏；「不再显示」永久记住。向导可在「浏览器引擎」页重新触发。

从 CloakLite 升级？首次启动会非破坏性地拷贝旧数据与引擎；旧 `cb_` profile 完全兼容。

## 3. 配置（Profiles）

### 创建

- **+ 新建配置**：**只需填名字**——在受支持的主机上，平台默认跟随宿主系统（Mac 使用 macOS，Windows 主机使用 Windows），身份字段由指纹种子自动派生，其余都在「⚙️ 高级配置」里（种子、时区、语言、WebRTC、地理位置、硬件覆盖、DRM、窗口标题、Web App URL）。
- **🎯 业务预设**：一键预填一整套自洽身份（TikTok Shop US、Amazon 卖家 US、eBay UK、欧盟电商 DE、加密交易所 SG 等）。
- **⚡ 快速创建**：免表单一键建号。
- **📥 批量导入**：每行一个（`name, platform, locale, timezone, seed, webrtcIp`），也支持带表头 CSV。

### 日常操作

- **▶ 启动 / ⏹ 停止**。启动前会先跑安全检查（见「启动安全门」）。停止请求返回成功仅表示已受理，不代表浏览器已经退出或所有写入均已持久化；重启、导入或备份前应等待实际状态变为已停止。已确认的 Chromium 实例会先请求正常关闭，失败时的有界信号升级只是清退手段，不是数据保存保证。
- 卡片工具：✎ 编辑、🍪 Cookie、🧩 扩展、📦 导出备份、✏️ 重命名、📝 备注、🔒 锁定到本机、📋 日志、🧬 漂移检测、🖥 环境检测、📡 WebRTC 诊断、🎬 DRM、🖥 App 模式。
- **筛选与批量运营台**：按状态（运行中/已停止）和标签筛选，全选可见后批量启动 / 停止 / 分配代理 / 导出 / 删除；超过 10 个的批量删除需要勾选知悉框。

> **正在调查的数据完整性问题（2026-10-18）：** 使用 Chromium 152.0.7977.72 的隔离验收中，新写入的 LocalStorage 值在立即停止、重启后曾出现丢失或保留旧值，即使已观察到退出码为 0、没有退出信号，并收到 `Browser.close` 确认回包。先关闭页面再退出的实验也复现了丢失，已撤回，不能当作有效修复。等待“已停止”是必要条件，但不保证落盘。重要数据请另存独立且已核验的副本；测试全绿、“已同步”徽标或导出请求成功，都不证明浏览器最后一次写入已经保存。问题未解决前，不要覆盖唯一已知完好的备份。具体已测范围与失败证据见[功能审查](review/ipc-api-health-functional-audit-2026-10-18.md)。

### 回收站（防误删）

删除的 profile 进入 **7 天回收站**——成功 toast 带「撤销」按钮，页头可查看与恢复；超过保留期自动物理清除。

### 锁定（团队签出）

🔒 **锁定到本机**表示该 profile 被本机签出。其他设备的 push 会被硬拦截（确认后仍可强制覆盖）。锁随同步传播。

### WebGL 画像、原生 GPU 能力与代理 DNS

以下是配置与启动规则，不代表已经通过 Ping0 实站或交付包验收。

- 托管 Chromium 要求受支持且匹配的宿主系统：Mac 使用 macOS，Windows 主机使用 Windows。新建、预设和未指定平台的批量导入统一使用该宿主默认值。显式指定的外来系统配置仍可便携保存，不会被后台改写，但本机不兼容的启动会被拒绝。WebGL 画像不能把 Metal 硬件变成 Windows D3D GPU。
- **仅 macOS 原生 ARM64 主进程＋所选 ARM64 Chromium＋托管模式**使用 Apple WebGL 画像。现有四个 Apple 画像的厂商均为 `Google Inc. (Apple)`，渲染器分别为裸字符串 `Apple M1`、`Apple M2`、`Apple M3`、`Apple M2 Pro`。这是模拟身份，不是物理显卡型号证明；**WebGPU、实际 GPU 能力及绘制仍原生**。
- 新建或编辑配置时，可在「高级硬件指纹」填写 `gpuVendor` / `gpuRenderer`，或留空由种子选画像。显式值是平台画像组合的部分约束，必须与 CPU、内存、屏幕等共同匹配同一受支持组合，不能随意拼接；受支持的旧 ANGLE／裸型号精确别名仍兼容，输出按上述身份规范化，不支持模糊型号猜测。
- **Intel、Rosetta、架构未知及其他 Chromium 平台仍用原生 GPU 身份**；显式 GPU 覆盖请求不受支持时拒绝启动，不会悄悄忽略或删除元数据。请纠正为受支持组合，或手动清空这两个字段。界面可编辑只表示可保存元数据，不证明宿主或所选内核有能力；由主进程在启动时权威校验，不从网页 UA 推测。Firefox 保留原画像组合的选择约束，但使用 Gecko 独立呈现：Apple WebGL 画像输出 `Apple` / `Apple M1, or similar`，这是 Gecko 的粗粒度隐私分组，不是物理型号或 Chromium ANGLE 名称。默认 prefs＋BiDi 路线通过引擎偏好设置 WebGL，WebGPU 保持原生，不再用仅改页面的 GPU shim。媒体设备枚举也保持原生，以保留权限策略拒绝、授权前标签隐藏和可用于选择设备的 ID；该 fallback 不承诺合成设备列表。
- Mac 上的旧 Windows 配置需要明确编辑为 **macOS**，然后在 **Studio 中停止该浏览器，再重新启动**。改种子不会改变操作系统；刷新网页或重启 Studio 可能仍复用旧浏览器。启动身份、模式或 DNS 设置改变后需明确重启；证据不足或已变化时返回 `restart-required`，不会自动杀掉或替换运行进程。
- 关闭指纹身份（直通／`off`）时 GPU 身份保持原生，不生效的已存身份字段会被忽略，但代理 DNS 隐私仍保留。原生 GPU 或系统家族一致，不等于所有高熵 CPU 与系统版本字段都已匹配物理主机；这些值会另行记录并核对跨表面一致性。
- 固定 HTTP/SOCKS 代理默认在出口解析目标域名，关闭指纹身份时也一样。经过验证的 HTTPS `managedSecureDnsUrl` 才显式选择严格代理 DoH；该引擎使用此选项需要托管身份模式。代理侧 DNS 走 TCP；显式严格 DoH 才选择原生 QUIC/MASQUE。代理失败时不新增直连回退。
- 仅触发 DNS 的提示与真实资源请求走不同路径，默认代理侧 DNS 和显式严格 DoH 的预解析策略也有区别；本地解析拒绝保护不等于代理出口无法解析。Ping0 包含 DNS-prefetch、CSS、Image 和 STUN 四路探测，不能只用预取路径解释计数。
- 启动日志里的 **configured（已配置）** 不是 DNS 事务成功证据。第三方 `resolver_count=0` 本身既不能证明 fake-IP，也不能证明所有 DNS 均失败。普通代理网页请求成功，也不等于检测站探针或严格 DoH 事务通过；须关联真实解析与路由证据。不保证任意第三方固定评分。算法、返回字段与分层排错见 [Ping0 检测机制](PING0_DETECTION.md)。
- 修复后，旧 GPU 基线可能发生漂移，请审查实际变化。应用不会自动删除基线、重置授权或改写已有配置。

### 上报配额与网站存储错误

- **上报配额（MiB）**是身份元数据，不是可写容量设置。Chromium 受管模式的 `storageQuota` 修改存储估计／旧配额 API 返回给网站的配额；MiB 为 1,048,576 字节。留空／自动当前上报 120,000 MiB，并非宿主磁盘可用空间；它不预留磁盘、不增加浏览器实际存储上限，也不扩大 LocalStorage。
- `localStorage.setItem()` 的 `QuotaExceededError` 表示该次写入失败。LocalStorage 有独立的存储区上限，同区所有键和值（包括其他缓存）共同计入；可能是一个缓存项过大，也可能是总占用已满。调大上报配额不能修复它，且它不同于“写入成功后退出丢值”。不要把清空含登录态的站点数据作为自动补救。
- CSP 拦截 inline script 时，应核对受影响 frame 与脚本发起方，区分网站、扩展或显式自动化代码；`unsafe-eval` 不授权任意 inline script。iframe 的 `allow-scripts`＋`allow-same-origin` 警告描述该文档的 sandbox 配置，不代表已发生逃逸。两类警告都不是关闭 CSP 或浏览器沙箱的理由。

### 指纹信任闭环

- **🧬 Drift**：只对比实时指纹与已存基线，不修改基线；在「浏览器引擎 → 启动安全门」启用对应开关后，高风险漂移可阻断启动。
- **锁基线**是独立写入操作。「已建立基线」不代表健康通过；风险采集先保留旧基线，只有明确确认已审查的快照后才替换。确认过期或相关状态变化时，必须重新采集审查。
- **🖥 Env**：报告主机 DNS 配置、字体目录，以及浏览器运行时实际测得的字体暴露和 rAF 帧间隔。探针失败或证据不完整时保持未验证。本地 DNS 存根／路由器不能证明上游国家；已保存或启动时的代理配置也不能证明实际浏览器 DNS 交易成功。缺少启动证据的运行进程保持未知，需通过正常流程重启后复核。
- **📡 WebRTC**：检查当前页面的 ICE 候选地址暴露，包括候选里的关联地址。不建立远端 peer，也不认证连线延迟；RTT 未测不能视为延迟正常。构造／offer 错误、WebRTC 不可用、空候选或未完成探测都不是通过。停止状态下启动配置需要确认，并遵守正常启动权限。
- **一致性**只检查已保存字段与缓存代理信息，不是实时出口检测；没有缓存冲突仍为未验证，不能标为实时通过。**外部风险检测**经确认后打开第三方检测页；打开页面不代表已导入评分或健康通过。
- **历史与卡片**使用主进程已保存的结论：通过、警告、风险、错误、不可用、未验证、已取消或已建立基线。旧记录缺完成证据时不升级为通过。清除会同时移除详细记录和摘要；已取消或清除的在途结果不能迟到恢复历史。取消是请求，底层探针实际结束前仍占用任务位置，取消也不会停止浏览器。
- **📋 日志**：该 profile 的最近审计活动 + 浏览器启动日志尾部。

## 4. 代理

- **+ 添加代理**（HTTP / SOCKS5 / SOCKS5H，可选凭据与绕过列表）。也可 **📥 导入** 粘贴列表（`type://user:pass@host:port`、`host:port` 或 CSV）、**📤 导出** CSV。
- **不强制你用代理**：全新安装的 profile **直连**启动，直到你添加代理并标记 ★ 默认。profile 弹窗里会显示「直连（未配置默认代理）」，绝不偷偷走路由。
- **🔍 检测**：测延迟、出口 IP、国家、时区，并标记 **🏭 机房（IDC）/ 公共代理**出口——这是账号风控最常见的来源。
- **健康分**：每次检测滚动更新健康分、历史时间线和建议（例如「更换住宅出口」）。
- **轮换与备用**：为代理配置备用列表；主代理劣化时 profile 自动切到第一个健康备用，恢复后自动回切；🔄 可手动轮换。
- **📎 绑定**：一个对话框把代理批量绑到多个 profile；**📱 二维码**导出完整代理 URI（含凭据——请像密码一样保管）。

## 5. 浏览器引擎页

- **独立引擎**：显示已安装构建；可按 profile 钉住精确版本以便回滚；**Verify** 运行严格校验。
- **🎬 Widevine / DRM**：发现宿主 CDM、暂存托管副本、按 profile 启用，流媒体站可播。
- **🛡 启动安全门**（每个开关即改即存）：
  - 一致性冲突拦截（时区/语言/WebRTC 与代理）
  - 机房/公共代理出口拦截
  - 指纹漂移拦截
  - 环境风控拦截
  拦截发生在浏览器打开之前——保护的是账号，不只是提示。
- **🔄 应用更新**：检查更新清单、暂存、激活、回滚；内置崩溃循环自动回滚。

## 6. 扩展

全 profile 共享的私有目录：导入本地 CRX/ZIP 或解包目录、从 Chrome 商店添加、打标签、标记共享。profile 只需勾选启用哪些条目。解压有加固（路径穿越 / 符号链接拒绝、哈希校验）。

## 7. 账号

保存平台账号（URL、用户名、标签）并绑定 profile。密码静态加密且**永不展示**；「复制密码」在主进程解密后写剪贴板。**📥 批量导入**可为每个账号同时创建一个绑定的 profile；**⬇ 导出 CSV** 只含元数据。团队工作区启用后，viewer 角色不能读取或修改账号密码。

## 8. 智能体（AI）

- **配置**：OpenAI 兼容或 Claude，填 URL/密钥/模型（密钥静态加密、处处脱敏）。文件访问模式：沙箱目录 / 信任目录 / 完全开放（高风险）。
- **对话**：流式对话 + 工具调用——智能体可以导航、点击、填表、截图、读 Cookie，对你指定的 profile 执行 HTTP/数据库/文件工具。敏感 HTTP 写操作和破坏性数据库操作会弹**审批对话框**（允许一次 / 总是 / 拒绝）。
- **技能**：可复用的提示词/工具配方；支持导入导出共享目录。
- **🔌 Adapter Hub**：15 个平台的版本化选择器配方（Amazon、Shopee、TikTok Shop、Instagram、Google Ads、X、LinkedIn、YouTube、交易所、欧盟商城…），智能体按页面加载用于登录检查与数据采集。
- **运行记录页**把每次跑动记成分步轨迹（工具、变量、耗时）以便审计。

## 9. 自动化

规则 = 触发器（cron、单次、profile 启动/退出事件）+ 动作（启停 profile、跑智能体任务、同步推拉、沙箱 JS）。执行是**持久化 job**：排队、并发受限、超时保护、指数退避重试，Jobs 列表可视可取消。月度/年度 cron 的 24.8 天溢出 bug 类已被回归测试覆盖。

## 10. 同步与团队工作区

1. **配置**：endpoint、bucket、AccessKey、SecretKey（静态加密）。
2. **起飞前预览**显示 push/pull 会动到什么；**Team Diff** 对比本地与远端，push 会**移除远端数据**前会先警告。
3. **团队工作区（RBAC）**：owner / admin / member / viewer 角色随同步传播。viewer 不能推送、下载或修改同步设置；强制推送需要 admin 或 owner。
4. **签出锁**（见「配置」）阻止遵守协议的客户端覆盖其他设备的签出，不代表跨设备原子事务或 CAS 保证。

**看清结果，再决定是否重试：**
- profile 的**已同步**仅证明可迁移配置与 `Preferences` 符合当前 endpoint/bucket 的已发布基线，不证明 Cookie、SQLite/WAL、LevelDB 或整个目录没有变化。**本地有改动**表示已保存到本地但不在该同步基线中；**未知**包括旧基线无法验证、同步目标改变等情况。读取列表不会自动升级旧标记。
- Compare 比较配置及有证据覆盖的 Preferences，并列出未验证、未比较的数据。比较后任一端内容变化，需要重新比较再应用旧决策。同一应用进程一次只执行一个推送/下载；“忙碌”不表示请求已排队。
- Cookie 导出区分“确实为空”和“来源不可用”；不可用时可能保留旧云端副本并给出警告。下载按合并方式导入 Cookie：空快照不清空接收端已有 Cookie，**已排队**不等于浏览器已导入。运行中的 profile 会跳过磁盘 Preferences 和 LocalStorage 恢复；推送不采集其运行中的 LocalStorage 数据库，可能保留旧远端副本并给出警告。
- 已停止 profile 的 LocalStorage 同步支持 Chromium 的 `Default/LocalStorage` 及可选 `LocalStorage-wal`，或旧版 `Default/Local Storage/leveldb`。SQLite 主库和 WAL 按组采集，不传 SHM；该组限 64 MiB，并有页数、帧数、schema 和校验时间限制。不支持的 schema、损坏组、非空回滚 journal、混合格式和跨格式覆盖会被拒绝，不会将其当作“数据不存在”。这不是 SQLite 格式/浏览器版本迁移工具，不同步 SessionStorage，也不保证 Firefox DOM-storage 全库恢复。必需的目录持久性不受支持时，SQLite 恢复会安全拒绝，包括明确不支持的 Windows 目录 fsync 路径。
- **部分完成**、**提交结果未知**、**需要恢复处理**都不代表已回滚。请查看分项结果和上次操作状态，不要反复重试或删除保留的恢复副本。LocalStorage 成功替换后也会保留旧库，待另外完成浏览器运行态验证，不自动删除。自动化只会对已证明本地、远端均未提交的失败尝试执行自动重试。
- **历史是另行选择的范围。** 普通数据代管同意不包含历史。请在同步设置中另外同意 **浏览历史／Firefox Places（包括书签、网址和标题）**，再选择今后的推送、拉取与自动同步是否包含它，并保存。旧设置默认未选择；仅给予同意不会自动开启历史上传。撤销此范围会停止今后的历史采集，但不会删除已存远端对象。
- **v3 envelope** 引用内容寻址的 **v1 历史 artifact**。实际 ZIP 字节必须先 PUT 上传并 GET 读回相等，再由主清单引用。描述符绑定快照 ID、同一配置 `dirId`、引擎、schema／版本、允许的相对路径及各成员 SHA-256／大小。Chromium 使用 `Default/History`，Firefox 使用配置根目录 `places.sqlite`；主库与可选 WAL 成组运输，不传 SHM。每组最多 64 MiB、合计最多 256 MiB，另有 schema、行、页、帧及校验时限。非空回滚 journal、变化中的文件、链接、超限、损坏、不兼容 schema 或无法确认已停止的归属都会拒绝新采集。可以保留之前已核验的对象，但明确显示**本次未重新采集**；没有旧对象则报告失败，不伪装为空或不存在。
- 历史校验仅打开含 WAL 的拥有副本，检查结构完整性、普通表 schema、精确类型值与关键关联；不 checkpoint／修复源库，也不用 `immutable` 忽略 WAL。不支持的 CHECK、生成列、表达式索引及虚拟表会被拒绝，而非执行其 SQL。源码已知的版本准入为 Chromium History 15–70（compatible version 至多 16）及 Firefox Places 52–86；这不证明每种指定／已装内核都能使用该库。已有接收端 schema 必须匹配，不会悄悄进行跨引擎或 schema 迁移。
- 拉取会先验证所选历史对象，再在**同一 `dirId`** 下恢复，不走 ZIP 导入的新 ID 路径。旧 DB／WAL／SHM／空 journal 完整组保留在 `.history-backup-*`，live 组不会留下旧 sidecar；应用前重新核对配置和运行归属。多文件发布**并非原子事务**：配置提交前的失败／取消，在归属允许时执行补偿。`HISTORY_RECOVERY_REQUIRED` 表示补偿未确认，重试前应检查保留的旧／新组和回执，不要删除唯一的恢复副本。
- **旧协议未覆盖**、**未选择**、**已确认源不存在**、**完整空快照**、**保留旧快照**与**失败**分别报告。旧备份／仅配置导入无法恢复从未上传的访问记录；源不存在不会清空接收端历史，明确选择的完整空数据库则会替换旧组。历史使用独立语义基线，对比带类型的行与关联，而非物理 main／WAL 哈希；checkpoint、SQLite 统计及已知维护元数据不会导致刚推送就变脏。请使用**复查已停止配置的历史状态**或 history-state API；状态区记录的覆盖不是新的本地读取，也不是浏览器历史界面的真实验收。
- 新快照先发布内容寻址扩展／历史对象，再发布主清单。新版可读取旧 envelope；旧客户端不保证理解 v3、历史 artifact v1、版本 2 的扩展包寻址或 SQLite LocalStorage 附件。共享新格式快照前，应一起升级团队客户端。
- 同步／导入回执分别报告**配置身份保持／改变／不可验证／旧配置缺 seed**及**运行指纹尚未复验**。已有 seed 会保留，不因拉取／导入重新随机。随包保留的 `fingerprintBaseline` 只是参考数据，不是实时对比证明。本机字体、缺失扩展包、实际内核／版本、操作系统及原生 GPU／引擎策略仍可能改变运行结果，需另行在同宿主／内核下实测对比。

S3 bucket 属敏感存储：同步会省略基础设施和账号凭据字段，但导出的 Cookie 与 profile 状态仍是真实账号数据，并非匿名化或端到端加密备份。

## 11. 数据与备份——请读一次

- 日常工作的 profile 数据保存在**本地**：`<user-data>/profiles/…`（cookie、localStorage），旁边还有加密凭据库与审计日志。另行配置的同步或导出可能也有副本，但仅有这些设置并不能证明已经具备独立备份。
- **磁盘故障可能毁掉本地 profile 数据。** 请将 **profile 导出备份保存在另一块磁盘或独立存储的云端备份中**，或使用 **同步到独立存储的 S3 bucket**。导出文件若仍放在同一块磁盘上，就无法抵御该磁盘故障。确认备份文件实际存在，并用非关键 profile 演练恢复。
- **7 天回收站只防误删，不防磁盘故障。** 回收站仍在同一块磁盘的本地存储区内，不是独立备份；永久清除或保留期结束后便无法再从回收站恢复。
- 备份包含敏感账号数据。浏览器加密的 cookie 与登录会话可能绑定原操作系统或设备；导出或同步 **不保证登录会话能在另一台机器上继续使用**。请单独保管账号恢复凭据，并做好重新登录的准备。
- 导出 ZIP 前先停止 profile。归档必须读回校验后才发布；已有目标只有获得明确许可才会替换。停留在原生文件对话框中不代表导出失败；已取消、已跳过、部分完成、完成但有警告是不同结果。
- 未解决或无法验证的 LocalStorage 救援事务会阻止归档（`ARCHIVE_RECOVERY_REQUIRED`）；应保留原材料，先处理报告的恢复问题。包含已完成 SQLite 救援历史的 ZIP 导入新 ID 时，所有救援字节与原回执保留到 `.profile-archive-recovery/<原ID>/Default/…`，并给出警告。这些非活动历史不是新 profile 的提交证明，也不是自动恢复的数据库，不会被悄悄删除。旧版副本在安全时仍保留于 live LevelDB 旁，不会为旧 ZIP 从未记录的告警伪造完成证明。
- **配置导入、独立 profile ZIP 和云同步范围不同。** 仅导入配置 JSON 不会复制浏览器数据库，也不会恢复访问记录。已停止 profile 的独立 ZIP 包含实际收集的浏览器文件（存在时包括 History／Places 与 WAL），并导入到新配置 ID；它不是云同步运输链。云端历史使用明确选择的 v3／v1 范围，在同 ID 恢复。应核对实际归档成员与逐项回执，不能用一种路径的成功替另一种作证。
- profile ZIP 不是全应用的 agent 数据库、凭据库、审计记录或全部设置备份；备份提醒只是建议，不是已有备份文件的证明。
- 「存储」页展示各 profile 磁盘占用，并保留数据安全提醒。

## 12. 集成面（开发者）

- **REST API** `127.0.0.1:26582`——`/openapi.json` 提供 OpenAPI 3.0，Bearer 鉴权（`AGENT_BROWSER_API_TOKEN`）。覆盖 profiles、proxies、accounts、automation、jobs、agent、DRM、team、updates。
- **MCP 服务器** `127.0.0.1:26581`，供 Claude Code / Cursor 等 MCP 客户端连接。同步工具为 `agent_browser_sync_status`、`agent_browser_sync_configure`、`agent_browser_sync_push`、`agent_browser_sync_pull` 和 `agent_browser_sync_history_state`；明确同意应来自用户意图，智能体不能从普通的启用同步擅自推断同意。
- **历史范围 API**：经鉴权的 `POST /api/sync/config` 接收 `{ "historyConsent": true, "includeHistory": true }`，分别记录同意并选择未来自动同步范围（member+）。推送／拉取接受可选 `history: true/false`；省略时继承已保存选择，不会给旧配置悄悄开启历史。`GET /api/sync/history/{dirId}` 返回独立语义状态、覆盖和新鲜度，不是完整恢复或实时身份凭证。JS SDK 方法为 `configureSync`、`syncPush`、`syncPull`、`syncHistoryState`；Python 对应 `configure_sync`、`sync_push`、`sync_pull`、`sync_history_state`。应先读取 HTTP 错误中的不完整／恢复回执，再决定是否重试。
- **Python 与 JS SDK**（`sdk/python`、`sdk/js`）——其中 `connectPlaywright` / `connectPuppeteer` 一行代码拿到绑定受管 profile 的真实 Playwright/Puppeteer 浏览器。profile 响应保留同步状态、范围和原因；HTTP 错误保留 `.status` 与有界 `.body`，应读取提交、结果与恢复字段，不要解析 message 猜测状态。错误正文超过 2 MiB 时，JS 的 `bodyTruncated` / Python 的 `body_truncated` 会明确标记，且不返回完整正文。正文缺失、被截断或运输超时都不能证明没有写入，不应盲目重试。

## 13. 推荐操作清单

- 确认你对每个账号、站点、数据集都有授权。
- 一个业务一个 profile；不相关账号间绝不共享 cookie。
- 正式账号前先 **Detect** 代理并消除 🏭 机房警告。
- 引擎升级或宿主变更后跑一遍 🧬 Drift / 🖥 Env。
- API 密钥与同步凭据妥善保管；导出物虽去密钥但仍属敏感。
- 有异动先看 📜 活动审计——每个敏感动作都有记录。

## 14. 新手 7 天养号 SOP（#94：先养号再干活）

> 50% 的"不好用"是不会用。反检测 ≠ 防封：新号 + 新 IP + 高频操作 = 必死。按下表渐进，一号一 IP 一环境。

| 天 | 只做 | 不做 |
|---|---|---|
| Day 1 | 建环境→四对齐检查→跑 🩺 检测（目标 ≥90 分）→只刷赞/收藏/评论 | 不发帖、不加好友、不改资料 |
| Day 2–3 | 每天 10–20 分钟浏览+互动；同设备新号间隔 ≥24h | 不批量操作、不换 IP |
| Day 4–5 | 少量发帖（1–2 条/天），回评论 | 不挂脚本、不 24h 在线 |
| Day 6–7 | 逐步加量；跑一遍 🧬 Drift + 🖥 Env 确认无漂移 | IP/时区/语言任一变化先停手 |

### 四对齐检查表（新建环境必跑）

1. **IP**：代理 Detect 通过，无 🏭 机房警告（机房 IP 先换住宅）。
2. **时区**：profile 时区 = IP 归属地时区（卡片 🩺 检测会标红 mismatch）。
3. **语言**：locale = 归属地语言（如美国 IP 用 en-US）。
4. **ASN/归属地**：IP 库归属地与三项一致；截图留存（售后纠纷凭证）。
5. 点 **🔒 锁基线**，审查并保存指纹参考；风险替换需要明确确认。若希望高风险漂移阻断后续启动，还需启用对应启动安全门；仅保存基线不会自动启用拦截，也不保证账号安全。

## 15. 故障排查

应用内的报错都是**人话 + 下一步建议**；原始技术信息始终可在开发者控制台查看。常见情况：

| 报错（意译） | 含义 | 处理 |
|---|---|---|
| 「该 profile 需要可用代理……已拒绝启动」 | 代理 fail-closed 保护 | 检查代理进程/端口与健康状态；重新分配或调整 profile 代理 |
| 「受管浏览器引擎缺失」 | 没有可用引擎 | 浏览器引擎页 → 安装指南 / 选择本地构建 |
| 「已拦截启动：指纹漂移……」 | 实时指纹 ≠ 基线 | 打开 🧬 Drift 查看；变更属有意则清除基线 |
| 「启动被环境风控门拦截」 | DNS / 字体 / 代理 DNS 发现 | 打开 🖥 Env 查看与修复 |
| 「连接被拒绝」 | 本地代理没起或端口不对 | 启动代理或改端口 |
| 「权限不足……（viewer）」 | 团队角色只读 | 请管理员在团队设置中调整 |
| Pull 跳过了部分 localStorage | 运行中 profile 受保护 | 停止后重试 pull |
