3. 剩余部分与建议排期

  1. TE-05 的 expectedVersion 乐观锁：跨设备 lock 检查已上线，这一半的风险已经消除。剩余的版本号 + 409 冲突返回需要改动所有写接口的签名，建议随下一次 API 版本调整一起做，不要单独夹带。
  2. TE-06 的模块拆分：门禁已就位（新增越界文件会阻断合并，不会再变差）。实际拆分按「先 local-agent.ts（3,334 行）、再 rest-api-server.ts（2,024 行）」的顺序分期，每期单独验收。
  3. PL-05 的结果导出：历史查看已可用，导出 JSON 未做——属于便利功能，优先级低于前两项。
一句提醒：这两项剩余都不是「坏的现状」，而是「还能更好」。当前代码没有因为它们的未完成而处于风险中——lock 检查已经把跨设备覆盖的真实风险堵住了，体积门禁已经保证模块化不会再退化。
