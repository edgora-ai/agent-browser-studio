**严重级别判定依据（rubric）**

| 级别 | 定义 | 典型触发 | 修复时限 |
|---|---|---|---|
| P0 | 数据丢失、凭据泄露、核心业务完全不可用，无绕过方案 | 配置覆盖、明文密钥落盘、启动即崩溃 | 立即（阻断发版） |
| P1 | 核心路径产生**错误结果**或不可用，发生概率高，用户可感知且不能自愈 | 谎报成功、状态不同步、错误不可见、规模化后性能崩塌 | 本迭代 |
| P2 | 明显影响效率/可维护性，有绕过方案，或仅在规模/边缘/竞态场景触发 | 无并发限流、校验滞后、巨型模块、无类型 | 下两个迭代 |
| P3 | 打磨项：低概率、影响面小、不改变结论 | 无障碍标签、图例缺失、无节流 | 排期规划 |

> 本次未发现 P0：安全边界（沙箱 / CSP / 凭据加密 / SSRF 阻断 / 审批门）已在代码中落实。本次非渗透测试，安全结论不构成审计意见。

## 2. Top 5 高优先级改进项

### Top 1 · 建可观测性底座（TE-01）— P1 · 系统架构

当前零遥测、零错误上报，渲染层只有 6 处 `console.error` 且不落盘。用户遇到启动失败我们不知道、性能退化我们看不见，**本报告所有量化验收标准当前无法被测量**。

- 结构化日志落盘（rotating，≤5MB/文件，7 天，带 traceId）
- 本地指标面板：launch 成功率、耗时 P50/P95、IPC 错误数、批量队列深度
- 可选外发遥测：默认关闭、端点自持、二次确认
- 一键导出诊断包（≤10MB，密钥已脱敏）

**预期收益**：把「无法度量」变成可度量，线上问题从「等用户反馈」变为分钟级定位；并为 Top2–Top5 提供验收数据来源。**它是其余四项的前置依赖。**

### Top 2 · 批量操作的正确性与并发治理（PL-01 + PL-02）— P1 · 产品逻辑

批量启动「发射后不管」：不等待 launch 结果，无论成败一律 toast「N profiles started」；且无并发上限，主进程限流（≤16）只覆盖自动化规则，不覆盖手动批量。

- `Promise.allSettled` 收集全部结果 + 并发上限 ≤4 + 队列可视化
- 聚合结果面板：成功/失败计数、失败清单（名称 + 原因 + 定位）、一键重试
- 支持暂停、取消；单项超时 20s 自动失败并放行队列

**预期收益**：消除「谎报成功」这一信任杀手；峰值并发进程从 N 降到 ≤4，100 profile 批量启动从「卡死」变为可预期；失败定位从人工逐个点降到一次点击。

### Top 3 · 反馈系统重构（UE-03，含 UE-04）— P1 · UI 与交互

Toast 单例互相覆盖（启动成功会被紧随的环境风险提示顶掉），无 `role="alert"`/`aria-live`，错误 3s 自动消失且无处可查。用户收不到错误 = 无法自愈。

- 可堆叠队列（≤3，FIFO）；错误类不自动消失
- `role="alert"` + `aria-live="assertive"`；含「查看详情」跳转
- 事件同步落 Activity 页，Toast 只作镜像
- 配套：表单改字段级 inline 校验，错误文案零技术字段名

**预期收益**：错误信息可达率 100%，减少「启动失败不知道为什么」类工单；改动量小、覆盖每一次操作，性价比最高。

### Top 4 · 检查类操作的副作用与外部依赖（PL-03 + TE-04）— P1 · 产品逻辑 + 系统架构

两个问题叠加在同一入口：点「Check Risk」会**静默启动**未运行的 profile；检测本身硬编码访问 `https://ping0.cc/env`，把该 profile 的指纹与出口 IP 发给第三方，无确认、无开关、无降级。

- 默认走**纯本地检测**（drift / env-risk / webrtc 三项已具备）
- 外部站点检测降为可选项：一次性确认 + 明示外发字段 + URL 可配
- 需启动才能检测时先弹确认并说明「将启动该 profile」
- 外部不可达 ≤10s 内降级为本地检测并标注原因

**预期收益**：同时消除合规风险（隐私外发无告知）、可用性风险（第三方 SPOF）与资源副作用；本地检测更快（≤15s）且不依赖外网。

### Top 5 · 列表性能与刷新不打断（TE-02 + UE-07）— P1/P2 · 系统架构 + 交互

列表每次刷新 `innerHTML` 全量重建，无分页/虚拟化/diff。后果：规模上不去（100+ profile 掉帧），且每次启动/停止都会打断勾选、滚动与下拉焦点。

- ≥50 条启用虚拟滚动或分页（每页 50）+ `dirId` keyed diff
- 无变更刷新跳过重绘；保存并恢复 scrollTop 与 activeElement
- 配套 TE-08：确立 5 条性能预算并接入 CI 冒烟

**预期收益**：可用规模从「几十个 profile」提升到「数百个」；消除高频操作的中断感。用户 profile 数只增不减，这是留存放大型问题。

## 4. 验收标准如何落地

1. **先装仪表再开车**：Top 1（TE-01）必须先做，否则其余 4 项验收数据无从采集。
2. **每条标准绑定一种验证方式**：自动化测试（DOM/网络/spy 断言）、E2E 脚本（Playwright Electron）、人工走查（5 名用户）、CI 门禁（行数/覆盖率/i18n key 一致性）。
3. **性能类必须有 fixture**：准备 100 / 1000 profile 两份 fixture，在固定机型（M 系列 16GB）上跑，回归超 10% 告警。
4. **本期不做的事**：不新增功能；不动指纹/引擎等安全敏感面；不出具安全审计结论。
