# Ping0 CDN 连接错误的宿主机对照（2026-10-21）

## 结论范围

在[完整十分钟页面观察](android-ping0-extended-wait-2026-10-21.md)仍无评分之后，按用户“为什么报错”进一步作宿主机对照。**不经临时测试代理，宿主机也能复现必需 CDN 资源的连接失败：两个 IPv4 地址可建立 TCP，但 TLS 握手未完成就收到 connection reset；两个 IPv6 地址未建立 TCP。主站 IPv4 同时正常返回 HTTP 200。**

因此失败不只是 App/模拟器内部或测试代理路径独有的现象，不能把它解释成评分计算缓慢或已完成的指纹 FAIL。它尚未证明临时代理没有其他问题，也没有定位发送 reset 的具体一跳。

## 方法

时间：2026-10-21T12:07:25Z；原有证据根、累计预算不变。没有启动模拟器、ADB、App 或新代理，没有修改产品配置、DNS/路由、全局代理、证书、TLS 或指纹。

- 仅两个已核对的公开域名：`ping0.cc`、`cdn.ping0.cc`。
- 先读取系统 `getaddrinfo` 结果，只连接其中有限的公网地址。
- 使用 `/usr/bin/curl`，本命令 `--proxy '' --noproxy '*'`；以 `--resolve` 固定刚取得的地址，但保留原 URL hostname、SNI 和正常证书验证。这不是 App 的 DIRECT 回退。
- 只请求主站 `/env` 与 CDN `/js/vue.min.js`，6 秒连接/15 秒总上限；最多 2 MiB，响应体输出到 `/dev/null`，不保留 body、headers、Cookie 或凭据。

## 实际结果

| 目标地址 | TCP 建连耗时 | TLS 完成耗时 | HTTP / 下载 | curl / 错误 |
| --- | --- | --- | --- | --- |
| 主站 IPv4 `104.218.235.243` | 0.238445 s | 0.484548 s | 200 / 53886 B | exit 0，TLS verify 0 |
| CDN IPv4 `104.21.81.48` | 0.056595 s | 未完成（计时 0） | 000 / 0 B | exit 35，`Recv failure: Connection reset by peer` |
| CDN IPv4 `172.67.188.46` | 0.199909 s | 未完成（计时 0） | 000 / 0 B | exit 35，`Recv failure: Connection reset by peer` |
| CDN IPv6 `2606:4700:3031::ac43:bc2e` | 未建立 | 未完成 | 000 / 0 B | exit 7，无法连接 |
| CDN IPv6 `2606:4700:3033::6815:5130` | 未建立 | 未完成 | 000 / 0 B | exit 7，无法连接 |

这并不排除 DNS 返回错误公网地址，也不证明所有 IPv6 目标都不可用。已确认的是本次有限地址上的运输阶段，不能将 `HTTP 000` 当作网站返回的 HTTP 状态，或把未完成握手的 verify 字段解释成确切证书根因。

## 为什么页面会保留 `{{...}}`

已核对的公开 HTML 将 Vue 和检测脚本放在 `cdn.ping0.cc`。主页面 HTML 能加载，不代表该独立域名的脚本也能加载。必需脚本拿不到时，模板没有正常挂载/初始化，因而仍能看到 `{{ animatedScore }}` 等原始内容，不能当成数字评分。

尚未确定 reset 来自 CDN 边缘/访问策略、网络运营商路径、中间设备还是其他原因。没有证据认定是 Ping0 识别了指纹、代理认证错误或证书失效；不通过关闭 TLS 校验来放行。

后续应先恢复测试出口到主站与必需 CDN 的共同可达性，再在实际 App 重新检测并核对全部依赖/完成计数。此次宿主机对照不是浏览器代理出口或完整指纹验收。
